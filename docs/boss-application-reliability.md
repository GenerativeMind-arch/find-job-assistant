## 已调整的责任边界

- Manager 负责单次投递超时与点击授权，单投、批投和 Agent 使用同一入口。点击开始前超时，关闭本次点击授权。点击开始后结果未返回，提示用户核对平台会话。
- 浏览器适配层负责检查详情链接、识别平台限制和判断点击结果。安全检查未通过或仍在冷却时结束整批，恢复由用户主动发起。
- 岗位记录写入后，会话补写、定制话术和辅助统计的失败保留已记录的投递状态。API 统一计算新增成功、此前已沟通、失败、待核对和未执行，界面直接使用汇总结果。

## 后续优先级

1. **持久化单次操作结果。** 给批次和岗位操作独立 ID，投递前写入待执行状态，使用事务保存完成或待核对结果。以平台可验证的已沟通状态作为确认依据。对待核对项提供人工确认和去重，避免刷新页面或重启后丢失上下文。
2. **让批次脱离长 HTTP 请求。** 创建批次后立即返回 ID，前端按 ID 查询进度，逐项显示取消、已完成与待核对。只允许取消尚未开始的操作。
3. **隔离浏览器进程并补充阶段指标。** 保留串行浏览器操作，将浏览器执行放到独立进程。分别记录导航、页面检查、点击和本地写入的耗时与结果。INFO 遥测只保留阶段、耗时和结果代码，便于在 DataKit 中追踪超时点。
